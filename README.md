# CRM закупок

Внутренняя система отдела закупок: поставщики, товары, заказы, частичные поставки, оплаты и задолженности, средневзвешенные закупочные цены за 6 месяцев, задачи, аналитика руководителя, журнал действий и импорт исторического Excel.

**Стек:** Next.js 15 (App Router, серверные действия) · TypeScript · PostgreSQL (Supabase) · Drizzle ORM · Tailwind CSS · Recharts · ExcelJS. Хостинг — Railway, файлы — Supabase Storage.

## Развёртывание: GitHub → Railway + Supabase

### 1. Supabase
1. Создайте проект на supabase.com и выберите регион, ближайший к Railway (например, `eu-central-1`).
2. **Project Settings → Database → Connection string → Session pooler**. Скопируйте строку и подставьте пароль базы — это `DATABASE_URL`. Session pooler работает по IPv4, а прямое подключение к Supabase у Railway по IPv4 недоступно.
3. **Project Settings → API**: возьмите `Project URL` (`SUPABASE_URL`) и ключ `service_role` (`SUPABASE_SERVICE_ROLE_KEY`). Ключ даёт полный доступ — храните его только в переменных Railway.
4. Бакет `documents` создаётся автоматически при первой загрузке файла. Он приватный: файлы отдаются только через приложение после проверки прав.

### 2. Railway
1. **New Project → Deploy from GitHub repo** → выберите этот репозиторий. Railway найдёт `Dockerfile` и `railway.json`.
2. **Variables** — заполните по образцу `.env.example`: `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `COOKIE_SECURE=true`.
3. **Settings → Networking → Generate Domain** (или подключите свой домен).
4. При каждом запуске контейнер сам применяет миграции (`drizzle/*.sql`) и создаёт роли и руководителя, если их ещё нет. Railway проверяет готовность по `/api/health`.
5. Каждый пуш в `main` разворачивается автоматически.

### 3. Первый вход и перенос данных
1. Войдите под `ADMIN_LOGIN` / `ADMIN_PASSWORD`.
2. **Пользователи** → добавьте закупщиков. Система покажет временный пароль, при первом входе сотрудник сменит его.
3. **Настройки → Импорт Excel** → загрузите `УчетЗАКАЗов.xlsx`. Проверьте предпросмотр: листы, сверку с итогами, дубли, ошибки, сопоставление столбцов. Назначьте закупщика каждому листу и подтвердите импорт. Импорт можно откатить, а повторная загрузка того же файла не создаёт дублей.

### Резервные копии
- Supabase делает ежедневные копии на платных тарифах (Pro: 7 дней, плюс Point-in-Time Recovery за доплату).
- **Настройки → Параметры и резервные копии → Скачать полную копию данных**: все таблицы в одном Excel-файле. На бесплатном тарифе скачивайте её регулярно.
- Полный дамп: `pg_dump "$DATABASE_URL" > backup.sql`.

## Локальная разработка
```bash
cp .env.example .env          # укажите локальный Postgres или Supabase
npm install
npm run db:migrate            # миграции + роли + admin
npm run dev                   # http://localhost:3000
npm test                      # тесты расчётов и разбора исходного Excel (TEST_XLSX=путь)
```
Изменили схему (`src/db/schema.ts`) → `npm run db:generate` → закоммитьте новый файл из `drizzle/`.

## Как устроено
| Каталог | Что внутри |
| --- | --- |
| `src/db/schema.ts` | схема БД: пользователи/роли, поставщики, товары, заказы → позиции, поставки → строки поставок, оплаты, задачи, документы, уведомления, журнал, план поставок |
| `src/lib/calc.ts` | чистые расчёты: автостатус заказа, контроль превышения, средневзвешенная цена, окна 6/12 месяцев, сравнение поставщиков |
| `src/lib/services/` | запросы с проверкой видимости (закупщик видит только свои заказы), агрегаты по заказам и поставщикам |
| `src/lib/import/` | разбор трёх форматов листов Excel, предпросмотр, импорт одной транзакцией и откат |
| `src/app/(app)/` | страницы и серверные действия. Права проверяются на сервере в каждом действии и запросе |

Ключевые правила:
- Итоги (поставлено, остаток, долг, средняя цена) **не хранятся**, а считаются из первичных записей.
- Поставка сверх заказа требует подтверждения руководителя.
- Удаление мягкое, удалённое восстанавливается в «Настройках».
- Каждое изменение пишется в журнал в формате «было → стало».
