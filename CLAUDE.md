# CRM закупок — контекст для разработки

Внутренняя CRM отдела закупок, заменяет Excel «УчетЗАКАЗов.xlsx». Интерфейс полностью на русском. Пользователи — закупщики без обучения, поэтому интерфейс должен оставаться простым.

## Стек и инфраструктура
- Next.js 15 (App Router, серверные действия), React 19, TypeScript, Tailwind 3, Recharts, ExcelJS.
- Drizzle ORM + `pg`. Prisma не используем: на закрытых серверах не скачиваются его движки.
- Хостинг: Railway, деплой по `Dockerfile` при пуше в `main`. Порт приложения — 3000 (`PORT=3000`).
- БД: Supabase Postgres через Session pooler. SSL включается автоматически по URL (`src/db/index.ts`).
- Файлы: Supabase Storage, приватный бакет `documents` (`src/lib/storage.ts`). Без ключей файлы пишутся в локальную папку.
- При старте контейнера `npm run start:prod` → `scripts/migrate.ts`: миграции из `drizzle/`, затем роли и admin.

## Команды
- `npm run dev` · `npm run build` · `npm test` (tsx --test; парсер тестируется на исходном xlsx через `TEST_XLSX`).
- Изменение схемы: правка `src/db/schema.ts` → `npm run db:generate` → закоммитить новый SQL из `drizzle/`.
- `npx tsc --noEmit` — проверка типов перед коммитом.

## Архитектура
- `src/lib/calc.ts` — чистые расчёты: `computeStatus`, `checkOverDelivery`, `weightedStats`, `priceWindow`, `compareSuppliers`, `monthlySeries`. Покрыты тестами.
- `src/lib/services/orders.ts` — SQL-агрегаты `ITEM_STATS` / `ORDER_STATS`, `orderScope(u)` (видимость), `assertOrderAccess`, `recalcOrderStatus`.
- `src/lib/permissions.ts` — права. Роль даёт права по умолчанию, `users.extra_permissions` — выданные дополнительно. **Права проверяются на сервере** в каждом действии и запросе.
- `src/lib/import/parser.ts` разбирает 3 формата листов (main / simple / plan). `importer.ts` строит предпросмотр, выполняет импорт одной транзакцией и умеет откат по `import_batch_id`.
- Страницы и серверные действия — `src/app/(app)/<раздел>/{page.tsx,actions.ts}`. Формы — `ActionForm` из `src/components/client.tsx`. Отправка ручная, чтобы React 19 не сбрасывал поля; поддерживается `needConfirm`.
- Журнал: `logActivity()` с `changes: {поле: [было, стало]}` на каждое изменение важных данных.
- Что нового: каждый новый функционал для пользователей — запись сверху в `src/lib/changelog.ts` (простым языком, где это найти). При старте контейнера `announceUpdates()` (`src/lib/updates.ts`) один раз рассылает необъявленные версии всем активным сотрудникам в уведомления; история — страница `/whats-new`.
- Календарь поставок `/calendar`: недопоставленный остаток по плановой дате заказа + `supply_plan_entries` (план, не факт).

## Принципы (не нарушать)
- Итоги не хранятся: «поставлено», «остаток», долги и средние цены всегда считаются из позиций, поставок и оплат.
- Цена не указана → `null`, не ноль. В средних ценах такие строки не участвуют.
- Средневзвешенная цена = Σ(qty × фактическая цена поставки) / Σqty по дате фактической поставки, без отменённых заказов и удалённых поставок. Окно 6 месяцев — «скользящее» или «календарное» (настройка `priceWindowMode`).
- Долг по заказу (сумма заказа − оплаты) и долг по отгрузке (поставлено − оплаты) показываются раздельно. Авансы без счёта (`payments.order_id IS NULL`) входят только в сальдо поставщика.
- Поставка сверх заказа возможна только с подтверждением руководителя (`overDeliveryApproved`). Закупщик может лишь отправить запрос.
- Удаление мягкое (`deleted_at`), восстановление — в Настройки → Удалённые.

## Решения по Excel, принятые по умолчанию (ждут подтверждения заказчика)
1. Закупщиков в Excel нет — при импорте закупщик выбирается для каждого листа.
2. 64 позиции поставлены сверх заказа — перенесены как есть с флагом «превышение подтверждено».
3. 98 позиций с вручную перезаписанным «остатком» — помечены `is_closed`.
4. Авансы вверху листа «СозвездиеМЕЧТЫ» (15 шт., 13,2 млн ₽) — платежи поставщику без счёта.
5. «ост.поставщики»: нет наименований и дат поставки — позиция = примечание, поставка на дату счёта с `date_assumed`.
6. «ПРИБОРЫ» — план поставок (`supply_plan_entries`), а не факт.
7. «ООО Бьютирин (копия)» — устаревший снимок, по умолчанию не импортируется.
- В Excel формула «ИТОГО поставки» на «ООО Бьютирин» охватывает не все столбцы. Система насчитывает 832 923 шт., Excel — 818 335. Верно 832 923.
- Плановой даты поставки в Excel нет: она равна дате заказа + 30 дней (настраивается).
